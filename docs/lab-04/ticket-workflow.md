## Behavior

The backend enforces the complete status matrix and checks resolution under the parent Ticket lock: at least one completed Action with a nonblank result, no planned/in-progress Actions, and no outstanding non-cancelled follow-up. Requester resolution indication remains advisory. A blocked Resolve returns structured `RESOLUTION_BLOCKED` details; stale versions or an owner changed during the operation require an explicit refreshed retry.

Status writes lock the actor and observed owner in sorted User-ID order before locking the Ticket, revalidate eligibility and ownership, and append the immutable transition event atomically with the Ticket version and resolution metadata. Claim records an event only when it actually changes New to Open. Failure to write history rolls back the Ticket update. No new migration is needed; the foundation migration supplies the event table and metadata fields.

Entering Resolved sets an actual timestamp; closing preserves it, including an explicitly estimated legacy timestamp. Reopening clears resolution metadata and the Requester advisory. Legacy records without a timestamp are labelled honestly. Re-resolution checks the current Actions again. Ticket history is public to authorized staff and the owning Requester, paginated in stable timestamp/ID order, and reports the migration boundary without inventing earlier transitions or exposing email addresses.

The UI distinguishes actionable blockers from version conflicts, links back to Actions Taken, and refreshes metadata/history after success. Status controls stay disabled during background refresh and preserve a still-legal selection. Confirmation controls wrap on mobile. Action date inputs preserve milliseconds so work created within the same second as a Ticket is not rounded before Ticket creation.
